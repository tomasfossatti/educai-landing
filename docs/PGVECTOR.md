# pgvector evaluation and rollout

## Decision

Educai already stores content chunks in PostgreSQL, so hybrid retrieval uses the `pgvector` extension in that same database rather than introducing a separate vector service. This keeps authorization, content state, versions and provenance in one transactional boundary. The committed Docker setup uses the official `pgvector/pgvector:pg16` image; hosted PostgreSQL must expose the `vector` extension and permit the migration role to run `CREATE EXTENSION`.

The first implementation fixes vectors at 1,536 dimensions and defaults to `text-embedding-3-small`. Changing dimensions requires a planned schema migration and full re-embedding; changing to another 1,536-dimensional model only requires a backfill because `embeddingModel` prevents vectors from different models being compared.

## Compatible rollout

The migration is additive and non-destructive:

- `ContentChunk.embedding`, `embeddingModel` and `embeddedAt` are nullable.
- Existing `Message.sourceChunkIds` remains in place during the compatibility period.
- New responses also write normalized `MessageSource` rows in the same transaction as the assistant message.
- Retrieval always computes lexical candidates. Semantic generation/query failures are logged with IDs/counts and fall back to lexical candidates.
- Only chunks whose material is `ACTIVE` enter either candidate set. `DRAFT` and `RETIRED` content may have an embedding for lifecycle/backfill purposes but is never retrieved.

Apply migrations before deploying application code. Environments based on a plain PostgreSQL image need the pgvector package installed first; the migration should not be marked as applied without the extension because the application schema relies on the `vector(1536)` type.

## Embedding provider and privacy

Configure `EMBEDDING_API_KEY`, optionally `EMBEDDING_API_URL`, and `EMBEDDING_MODEL`. With no embedding key, enrichment is deliberately skipped and lexical retrieval continues to work. The endpoint must implement the OpenAI-compatible embeddings response shape and return 1,536-dimensional vectors.

Embedding requests contain material chunks or the current retrieval query. Retry/error logs contain only attempt number, model, item count, course ID when applicable, and a bounded provider error message generated by Educai; they never include chunk, query or conversation text.

## Backfill and operations

New material versions are enriched after their chunks commit, and activation re-attempts enrichment for the latest version. A provider failure does not delete or invalidate lexical chunks. For historical rows, run an application-level batch that calls the same embedding service by version; nullable fields make rolling back or pausing that backfill safe.

Monitor `embedding_generation_failed` and `semantic_retrieval_failed`. The HNSW cosine index accelerates semantic lookup. For this pilot-sized corpus, lexical scoring still examines up to 400 active chunks; revisit database-native full-text search and index tuning as the corpus grows.
